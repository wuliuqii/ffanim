# ffanim 总体架构设计

> 项目：ffanim —— Rust + Typst + Vello 的数学动画引擎（manim 替代品）
> 依赖文档：《01-调研对比报告》

---

## 1. 设计目标

### 1.1 一句话定位

**用 Rust 写数学动画**：保留 manim 的数学语义与动画词汇（play / Transform / 公式变形），拥有 fframes 级别的现代 Rust 工程管线（快、可并行、无外部依赖、对 AI Agent 友好）。

### 1.2 设计原则

| 原则 | 含义 | 来源教训 |
|---|---|---|
| **两阶段时间轴** | 构建期求值（记录动作）与渲染期求值（纯查表）严格分离 | manim 每帧全量重算太慢；Motion Canvas 验证此模型 |
| **每帧纯函数** | `render_frame(frame) -> DrawList` 无副作用、确定性 | fframes；天然支持并行与缓存 |
| **单一对象表示** | 一套矢量数据结构同时服务 GPU/CPU 渲染与预览 | manim 双渲染器双类层级是复杂度灾难 |
| **进程内公式排版** | Typst 作为库嵌入，绝不 spawn 外部进程 | manim LaTeX 依赖地狱；Javis 生态教训 |
| **Agent 可验证** | 渲染前静态校验 + 渲染后可视化产物，全部 CLI 化 | fframes 核心洞察 |
| **数据驱动** | 场景参数、主题、样式均从外部文件加载，代码只含结构 | 用户约束 |
| **不过度设计** | 模块化场景架构，杜绝 singleton 滥用与假抽象 | 用户约束 |

### 1.3 非目标（明确不做）

- 不做视频编辑器 GUI（只做预览与检查工具）；
- 不做 3D 场景（M1~M5 范围内，相机仅 2D 仿射；预留扩展）；
- 不做云端分布式渲染（单机并行即可）；
- 不自研编码器。

## 2. 需求定义

### 2.1 核心功能需求（F）

- **F1 矢量对象**：矩形/圆/多边形/路径/文本/图片；贝塞尔点阵表示；fill/stroke 样式；组合与布局（`arrange/next_to` 等价物）。
- **F2 公式排版**：Typst 语法书写公式（`tex!("x^2 + y^2")` 风格），排版结果拆分为可独立动画的字形/片段单元。
- **F3 公式动画**：`Write`（逐字形书写）、`TransformMatchingTex`（按 Typst 源结构匹配变形）、片段替换。
- **F4 动画系统**：`alpha + rate_func` 缓动；`Create/FadeIn/FadeOut/Transform/MoveTo/Scale` 基础词汇；`.animate()` 终态 builder 语法；`lag_ratio` 组合（并行/顺序/错峰）。
- **F5 场景与时间轴**：多场景组织（`Scene trait`），场景重叠过渡；updater（求值期信号，驱动随帧变化的对象属性）。
- **F6 坐标系**：`Axes/NumberPlane`，`c2p/p2c` 映射，函数图像绘制。
- **F7 渲染导出**：PNG 单帧 / MP4（H.264）整片；1080p30 起步；ffmpeg 子进程管道编码。
- **F8 实时预览**：winit 窗口，可播放/暂停/逐帧/拖动时间轴。
- **F9 Agent CLI**：`render / frame / strip / onion / inspect / snapshot / timeline`，全部支持 `--json`。
- **F10 音频**（后期）：音轨声明、按音频长度定时长（`Duration::FromAudio` 语义）、基础混音。

### 2.2 非功能需求（NF）

- **NF1 性能**：1080p30 典型教学视频（~120s）渲染 ≤ 视频时长（参考 fframes：128s 视频渲染 36s）；公式排版结果全程缓存，零重复排版。
- **NF2 零外部依赖**：无 TeX、无 Node、无 Python；ffmpeg 找不到则自动下载二进制。
- **NF3 确定性**：同输入同输出（快照测试可复现）。
- **NF4 可扩展**：渲染后端、编码后端、动画类型均为 trait，可第三方扩展。
- **NF5 数据驱动**：主题/样式/场景参数从 JSON/RON 加载。
- **NF6 API 稳定性优先**：宁可显式冗长，不做魔法（fframes 作者教训的反面：他用 5 年才敢发布）。M1~M3 阶段允许破坏性变更，M4 起语义化版本。

## 3. 系统架构

### 3.1 模块划分（Cargo workspace）

```
ffanim/
├── crates/
│   ├── ffanim-core      # 对象模型 + 时间轴 + 动画系统（无渲染依赖）
│   ├── ffanim-typst     # Typst 嵌入 + Frame→Vello 适配 + 公式分片
│   ├── ffanim-render    # Vello GPU 渲染 + vello_cpu 兜底 + 相机
│   ├── ffanim-encode    # ffmpeg 子进程管道编码 + 音频 mux
│   ├── ffanim-audio     # 音轨声明与混音（后期）
│   ├── ffanim-preview   # winit + wgpu + egui 实时预览
│   ├── ffanim-cli       # Agent 工具链（render/inspect/strip/...）
│   └── ffanim           # 门面 crate（re-export + Scene DSL 宏）
├── themes/              # 数据驱动主题（JSON）
└── docs/
```

**依赖方向**（单向，无环）：

```
ffanim → core / typst / render / encode / cli
cli → core / render / encode / preview
preview → core / render
render → core
typst → core
core → （无内部依赖，仅 geom/curves 等基础工具）
```

### 3.2 核心设计决策：时间轴两阶段模型

这是全项目最重要的决策，解决"manim 的可变场景模型如何映射到 Rust"。

**阶段一：构建期（build，运行一次）**

```rust
// 用户代码：命令式书写，但只记录"动作"，不求值像素
impl Scene for PythagorasScene {
    fn build(&self, tl: &mut Timeline) {
        let tri = Polygon::right_triangle(3.0, 4.0);
        let eq = Tex(r#"a^2 + b^2 = c^2"#);
        tl.play(Create(tri).duration(1.0));
        tl.play(Write(eq).lag_ratio(0.1));
        tl.play(eq.animate().shift(UP * 2.0), tri.animate().fade(0.5));
    }
}
```

`Timeline` 内部把每个 `play()` 记录为带起止帧的 **Action**（起始帧 = 游标推进）。构建产物是静态的：

```rust
pub struct CompiledTimeline {
    pub duration_frames: usize,
    pub actions: Vec<ScheduledAction>,   // (frame_range, Action)
    pub scenes: Vec<CompiledScene>,
}
```

**阶段二：渲染期（render，每帧纯函数）**

```rust
// 确定性求值：frame -> 该帧所有对象的最终状态 -> DrawList
fn render_frame(&self, frame: Frame, tl: &CompiledTimeline) -> DrawList;
```

每个 `Action` 在构建期已捕获"起始快照 + 目标快照"（即 manim 的 `begin()/end` 预计算），渲染期只做 `start.lerp(end, rate_func(alpha))` 查表插值。updater 表达为构建期注册的**信号节点**（如 `ValueTracker` 快照 + 依赖关系），同样在渲染期按帧求值，无运行时可变闭包。

**收益**：并行渲染无需加锁（时间轴不可变）、缓存友好（对象状态可哈希）、`inspect/strip` 等工具可跳帧求值、与 Motion Canvas 的 recalculate 模型同构（已验证）。

### 3.3 对象模型

```rust
// 一切可视对象的统一表示（借鉴 VMobject，但单层化，无 Mobject/VMobject 分裂）
pub struct Item {
    pub id: ItemId,
    pub kind: ItemKind,          // Shape(贝塞尔点阵) | Glyphs(字形段) | Image | Group(Vec<Item>)
    pub style: Style,            // fill/stroke (RGBA, width)，数据驱动可从主题加载
    pub transform: Affine2D,     // 平移/旋转/缩放
}

// 贝塞尔点阵：扁平存储，GPU 友好
pub struct BezPath { pub points: Vec<Point> }  // 三次贝塞尔：锚点+双控制柄
```

设计要点：

- **`Group` 即 Item**，避免 manim `VGroup` 只收 `VMobject` 的类型分裂；
- **变换挂在 Item 上**而非烘焙进点阵，`Transform` 插值 = 属性插值 + 可选路径 morph（锚点数对齐后插点）；
- 公式排版产物 = `Group(Glyphs...)`，天然支持逐字形 `Write` 与 `TransformMatchingTex`（按 Typst 源结构树匹配，替代 manim 的字符串 SequenceMatcher）。

### 3.4 渲染层

```rust
pub trait RenderBackend: Send + Sync {
    fn render(&self, draw: &DrawList, camera: &Camera, size: (u32, u32)) -> FramePixels;
}
```

- **GpuBackend**：Vello `Scene` + wgpu `render_to_texture` → 读回像素（预览路径直接 present 到 surface，不读回）；
- **CpuBackend**：`vello_cpu`（sparse strips）兜底，CI/无 GPU 环境使用；
- **静态内容缓存**：借鉴 fframes 哈希缓存——构建期对不随帧变化的 `Item` 子树（如静态公式、背景网格）计算哈希，渲染层缓存其已编码的 Vello `Scene` 片段，逐帧只重编码动态部分；
- **相机即 Item**：`Camera` 本身是可动画对象（位置/缩放/旋转），置于场景根部 —— 继承 manim "相机即 Mobject" 的好设计。

### 3.5 编码层

```
并行 worker(帧段) ──rawvideo(rgb24 pipe)──▶ ffmpeg ──▶ segment.mp4 ──▶ concat ──▶ final.mp4
                                              ▲
                          音频轨(wav) ─────────┘ (amix / mux)
```

- 默认 **ffmpeg 子进程 + stdin rawvideo 管道**（Ranim 同款，规避 libav 链接地狱）；`ffmpeg-sidecar` 思路：PATH 查找，找不到自动下载；
- 每个 worker 编码独立 segment（GOP 对齐），最后 concat —— 借鉴 fframes 分段模型；
- `ffmpeg-the-third`（libav 绑定）作为可选 feature，不进默认路径。

### 3.6 Typst 集成层（ffanim-typst）

```rust
// 1) 实现 typst::World（文件/字体/日期），约 200 行，参考 typst-as-lib
// 2) 排版一次，拿到官方中间表示
pub struct Formula { doc: PagedDocument }          // 排版缓存 key = 源码+字号+主题哈希
// 3) Frame 树 → ffanim 对象（关键适配层）
fn frame_to_items(frame: &Frame) -> Vec<Item>;     // FrameItem::Text → Glyphs(逐字形)
                                                   // FrameItem::Shape → Shape(点阵)
                                                   // FrameItem::Group → 递归
```

- 字形轮廓经 `ttf_parser` 取得（typst-render/text.rs 同款做法）；
- `TransformMatchingTex` 基于 Typst 源码的**语法结构树**匹配节点（比 manim 的字符串匹配更稳）；
- 排版结果进程内 LRU 缓存，同公式同字号只排一次 —— 解决 manim "每条公式 2 秒" 痛点；
- ⚠️ Typst 0.x 破坏性变更频繁：锁死版本，适配层隔离在单 crate 内。

### 3.7 数据流总览

```
用户 .rs 场景代码 ─┐
themes/*.json ────┼─▶ [构建期] Timeline::build ─▶ CompiledTimeline（含公式排版缓存）
media/ 资源 ──────┘                                      │
                                                         ▼
                        [渲染期] frame 求值 ─▶ DrawList ─▶ RenderBackend(GPU/CPU)
                                                         │ FramePixels
                                                         ▼
                        [编码期] 帧段并行 ─▶ ffmpeg pipe ─▶ segment ─▶ concat ─▶ mp4
                                                         ▲
        CLI 工具链(render/inspect/strip/onion/snapshot) ──┘ 同一管线复用
```

### 3.8 关键接口清单（v0 语义）

```rust
pub trait Scene {
    fn build(&self, tl: &mut Timeline);
}

// Timeline（构建期游标）
impl Timeline {
    pub fn play(&mut self, action: impl Into<Action>) -> &mut PlayHandle;  // 返回句柄可设 duration/lag_ratio
    pub fn wait(&mut self, seconds: f64);
    pub fn overlap(&mut self, seconds: f64);          // 下一个 play 与上一个重叠（fframes Overlap 语义）
}

// 终态 builder（manim .animate 等价物）
impl Item {
    pub fn animate(&self) -> AnimateBuilder;          // .shift().rotate().fade() → Action
}

// 缓动（继承 manim rate_func 词汇）
pub fn smooth(t: f64) -> f64;  // 及 linear / there_and_back / overshoot / rush_in ...

// Agent CLI（全部 --json，时间规格 DSL：3.2s / 120f / 50% / Scene@1.2s / a..b）
// ffanim render [--draft] | frame <spec> | strip <spec> -n 12 | onion <range>
// ffanim inspect | snapshot <spec> | timeline
```

## 4. 技术选型

| 领域 | 选型 | 版本 | 选择依据 | 备选与放弃原因 |
|---|---|---|---|---|
| 语言 | Rust (2024 edition) | stable | 性能、单二进制分发、与目标栈同生态 | — |
| 公式排版 | **typst** 嵌入 + `typst-kit`（字体） | 0.15.x | 进程内、增量缓存、官方 `Frame/FrameItem` 中间表示可自绘；Manim CE 0.21 已列为公式后端 | LaTeX/dvisvgm：外部进程依赖地狱，放弃 |
| GPU 渲染 | **vello** + wgpu | 0.11 | 纯 Rust、GPU 加速、与 wgpu 预览同栈；`Scene` API 匹配 DrawList 模型 | Skia（skia-safe）：C++ 绑定、构建重（fframes 因此付出 fork 成本）；tiny-skia：纯 CPU |
| CPU 渲染兜底 | **vello_cpu** | 跟随 vello | 同一语义模型，CI/无 GPU 可用 | resvg fork：需自维护（fframes 教训） |
| 文本/字形 | ttf_parser + parley/fontique | — | vello 官方文本栈；typst 字形轮廓提取已验证 | — |
| 编码 | **ffmpeg 子进程 + rawvideo 管道**，自动下载 | ffmpeg 7/8 | 规避 libav 链接矩阵/交叉编译地狱；Ranim 验证；nf2 零依赖要求 | ffmpeg-the-third：冻结+链接复杂，降级为可选 feature；纯 Rust 编码器（EffectCraft 路线）：工作量极端，放弃 |
| 预览 | winit + wgpu + **egui**（egui-wgpu 复用设备） | egui 0.34 | vello 官方 with_winit 模板路径；egui 提供时间轴 UI | — |
| 配置/主题 | serde + JSON（后续可加 RON） | — | 数据驱动约束 | — |
| CLI | clap derive | 4.x | 行业标准 | — |

**两个明确风险的技术已配置退路**：Vello alpha → vello_cpu 兜底 + 特效缺口（如 blur）M5 前不承诺；ffmpeg → 子进程为默认，libav 为可选。

## 5. 数据驱动设计

- **主题文件**（`themes/*.json`）：调色板、默认 stroke/fill、字体族、公式字号 —— `Style` 从主题加载，代码零硬编码颜色；
- **场景参数**：场景结构体字段支持 `#[params]` 派生，从 JSON 注入（如演示数据、坐标范围），同一场景代码可渲染不同数据版本；
- **媒体清单**：`media/` 目录由构建期扫描生成强类型清单（借鉴 fframes `include_media_dir!`，但用构建脚本而非 proc-macro，降低复杂度）。
