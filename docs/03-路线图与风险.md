# ffanim 路线图、风险评估与可行性分析

> 依赖文档：《01-调研对比报告》《02-架构设计》

---

## 1. 开发路线图

里程碑按**可交付、可验证**原则划分，每个里程碑结束都有一条可运行管线。排序依据：先打通"对象→渲染→编码"主链路（最大技术风险），再做数学语义（差异化价值），最后做体验与生态。

### M0 — 项目骨架

- Cargo workspace + 8 个空 crate + CI（fmt/clippy/test）；
- 主题 JSON 加载骨架（serde）；
- 交付物：`cargo build` 通过、CI 绿。

### M1 — 核心渲染链路（最大技术风险点，优先拆除）

- `ffanim-core`：`Item/BezPath/Style` 点阵模型、`Affine2D`；
- `ffanim-render`：Vello GPU 后端（Scene 编码、render_to_texture 读回）+ vello_cpu 兜底后端；
- PNG 单帧导出（`ffanim frame` 最小版）；
- 验收标准：画三角形+文字+圆，输出正确 PNG；GPU/CPU 两后端像素级一致性冒烟测试。

### M2 — 时间轴与视频导出

- `Timeline::play/wait/overlap` 构建期求值 → `CompiledTimeline`；
- 基础动画词汇：`Create/FadeIn/FadeOut/Transform/MoveTo/Scale` + `rate_func` + `lag_ratio` 组合；
- `.animate()` builder；
- `ffanim-encode`：ffmpeg 探测/自动下载 + rawvideo 管道 + 分段并行 + concat；
- CLI：`render [--draft]`、`timeline`；
- 验收标准：两个矩形+缓动+场景重叠的 30s 视频，渲染耗时 < 视频时长。

### M3 — Typst 公式（差异化核心）

- `ffanim-typst`：World 实现、排版 LRU 缓存、`Frame → Items` 适配层（字形/形状/组）；
- `Write` 逐字形动画、`TransformMatchingTex`（基于 Typst 结构树）；
- CLI：`inspect`（缺字体/溢出画布诊断）、`snapshot` 像素 diff；
- 验收标准：公式从字符串逐字形写出并变形为另一公式（manim `Write` + `TransformMatchingTex` 等价演示）；同公式二次排版 0 开销。

### M4 — 预览与坐标系

- `ffanim-preview`：winit + egui 时间轴（播放/暂停/逐帧/seek）；
- `Axes/NumberPlane`、`c2p/p2c`、函数图像；
- updater 求值期信号（`ValueTracker` 等价物）；
- 验收标准：正弦函数图像随 ValueTracker 动画，预览可逐帧检查。

### M5 — Agent 工具链补全与生态

- `strip/onion` 接触表、`audio analyze`（引入 `ffanim-audio`）；
- `Duration::FromAudio` 语义、音轨 mux；
- `cargo ffanim new` 脚手架 + 场景模板库；
- 官方 coding-agent skill（借鉴 fframes 发行策略）；
- 验收标准：agent 从空目录到出片全程无人工看片。

### 资源需求

- 人力：1 名开发者 + AI 结对（本项目即按 100% AI 辅助开发模式设计，API 显式化、CLI 可验证均为此优化）；
- 硬件：任意带 Vulkan/Metal 的开发机；CI 需无 GPU runner（vello_cpu 路径覆盖）；
- 外部资产：默认内置开源字体（如 NewCM 数学字体 + Noto Sans），主题与模板为数据文件。

## 2. 风险评估与应对

| # | 风险 | 等级 | 影响 | 应对策略 |
|---|---|---|---|---|
| R1 | **Vello 仍是 alpha**（滤镜未实现、glyph caching 未完成、conflation 伪影） | 高 | 特效能力受限、GPU 路径可能出现渲染错误 | ① vello_cpu 兜底后端保证可用性；② 架构上 DrawList 与后端解耦，必要时引入 Skia 后端为 feature（架构已支持，见 02 §3.4）；③ M5 前不承诺 blur/shadow 等特效 |
| R2 | **Typst 0.x 破坏性变更频繁**（0.13→0.15 已多次 breaking） | 中高 | 跟进成本持续 | ① 锁死小版本；② 隔离在 `ffanim-typst` 单 crate，`Frame→Items` 适配层是唯一接触面；③ 发布时声明支持的 Typst 版本区间 |
| R3 | **API 设计失败**（fframes 作者因 API 冗长 5 年未发布；早期 manim-rs 均死于此） | 高 | 项目最大软风险 | ① 两阶段时间轴模型作为顶层约束先行冻结；② 每个里程碑以"写出验收示例代码"倒推 API（示例驱动设计）；③ M1~M3 允许破坏性迭代，M4 冻结语义化版本 |
| R4 | ffmpeg 子进程管线的吞吐瓶颈（rgb24 带宽：1080p30 ≈ 187MB/s） | 中 | 渲染快但喂不饱编码器 | ① 预期在正常范围（fframes 同量级）；② 必要时换 yuv420 帧格式直喂（转换在 GPU 端做）；③ 保留 libav feature 作为性能逃生舱 |
| R5 | 公式→字形动画的匹配质量不及 manim（TransformMatchingTex 手感） | 中 | 核心差异化体验打折 | 基于 Typst 语法树匹配优于 manim 字符串匹配（结构性更强）；M3 验收标准即为此场景，不达标则迭代匹配算法 |
| R6 | 单人维护 + AI 辅助开发的连贯性 | 中 | 里程碑延期、架构漂移 | ① 本设计文档即架构宪法；② 数据驱动约束（主题/参数外置）降低代码量；③ 每里程碑强制 snapshot 回归测试 |
| R7 | 生态冷启动（无社区） | 低 | 传播受限 | 差异化足够尖锐（单二进制+快+agent 友好）；先服务自身视频创作需求，自用即验证 |

**风险总评**：无不可解风险。R1/R2 是外部依赖成熟度问题，均有已验证退路；R3 是本项目最需要持续投入的软风险，已通过架构决策（两阶段模型）和流程（示例驱动）前置缓解。

## 3. 可行性分析

### 3.1 技术可行性 — ✅ 成立

- **每条关键技术都有生产级先例**：typst 嵌入（typst-as-lib、Ranim）、Vello 渲染（vello with_winit 官方模板）、ffmpeg 子进程管道（Ranim、ffmpeg-sidecar 月下载 ~13 万）、分段并行+concat（fframes）；
- **组合路线已被完整验证**：Ranim = typst + wgpu + ffmpeg，与 ffanim 同路线；fframes 验证了 Rust 视频框架的生产化与发行（1.0、AUR、cargo install）；
- **性能目标有参照**：fframes 128s 视频渲染 36s（Skia GPU），ffanim 的 Vello 路径 + 静态缓存 + 分段并行在同一量级设计下可达；
- **唯一不确定项**（Vello 特效成熟度、字形缓存）不阻塞核心价值（数学动画以矢量填充/描边为主，滤镜是锦上添花）。

### 3.2 工程可行性 — ✅ 成立

- 8 个 crate 依赖单向无环，每层可独立测试；核心复杂度集中在 `ffanim-core`（时间轴/动画）与 `ffanim-typst`（适配层），其余为薄封装；
- 零外部依赖目标（NF2）由"Typst 库内嵌 + ffmpeg 自动下载"达成，分发只需一个二进制；
- 数据驱动约束（主题/参数 JSON）与"一场景一文件"的组织方式符合现有开发习惯。

### 3.3 价值可行性 — ✅ 成立

- **市场空位真实存在**（01 §4）：manim 有语义无工程，fframes 有工程无语义；
- **自用即刚需**：开发者制作数学/技术科普视频是第一用户场景，dogfooding 驱动迭代；
- **AI 时代分发红利**：agent CLI + skill 的发行策略已被 fframes 验证，且 ffanim 的目标用户（写代码做视频的人）与 AI 辅助开发人群高度重合。

## 4. 预期成果

1. **软件资产**：`ffanim` 单二进制 CLI + 8 crate 的开源 workspace（MIT），含主题/模板/示例库；
2. **能力基线**（M5 完成时）：
   - 用 Rust 代码描述多场景数学动画，含 Typst 公式的逐字形书写与结构化变形；
   - 1080p30 视频渲染耗时 ≤ 视频时长，全程无 TeX/Node/Python 依赖；
   - 实时预览器 + 完整 agent 验证工具链（inspect/strip/onion/snapshot）；
3. **验证方式**：M1~M5 每个验收标准均可在 CI 中机器判定（PNG snapshot diff、渲染耗时基准、公式动画示例）；
4. **长期方向**（超出本方案范围，仅预留扩展点）：3D 相机、WASM 预览编辑器、交互式 embed（manim GL 语义）、更多编码后端（AV1/WebM）。
