# ffanim 项目优化规划（v0.2 → v1.0）

> 制定日期：2026-10-12（M6 完成后）
> 定位：本文档是 [03-路线图与风险](03-路线图与风险.md) 的续篇。03 的 M0~M6 已全部兑现，
> 本文档覆盖"创作验证完成之后、走向公开可用"阶段的系统优化。
> 原则：每项工作必须给出**验收标准**（可衡量）与**回退方式**（可调整）。

## 0. 现状基线（2026-10-12）

| 维度 | 现状 |
|---|---|
| 代码量 | 8 crate / 约 5790 行（含测试与注释） |
| 最大文件 | core/timeline.rs 869 行、cli/main.rs 651 行、typst/lib.rs 600 行 |
| 测试 | 全部内联 `#[cfg(test)]`，约 49 个测试；无 `tests/` 集成测试 |
| CI | fmt + clippy(-D warnings, CPU/GPU 两矩阵) + test |
| 版本 | workspace 0.1.0；tag v0.3-m3 / v0.4-m4 / v0.5-m5（里程碑 tag，非 semver） |
| 文档 | docs/ 3 篇设计文档；README 未随 M2~M6 更新；无 CHANGELOG |
| 已验证能力 | 960x540@30fps 实时率 8.6~10.4x；公式/坐标系/tracker/音轨/预览全通 |
| 未验证承诺 | NF1（1080p30 ≤ 视频时长）、R4（rgb24 带宽瓶颈）从未实测 |

结构性事实（审视发现）：

1. **相机未实现**。02-架构设计承诺"相机即可动画 Item"，代码中无 camera/viewport 任何实现。所有构图靠手摆坐标。
2. **ffanim-encode 反向依赖过重**。encode 仅使用 core 的 `Error/Result` 两个类型，却依赖整个 core（含 rustybuzz 等重依赖的编译传递）。
3. **单文件巨石模块**。timeline.rs 同时承担：动画构造（Anim/AnimKind）、调度编译（Timeline/compile）、求值（CompiledTimeline/render_frame/updater）三种职责；cli/main.rs 一个 match 手写 11 个子命令；typst/lib.rs 混合引擎/公式/匹配三层。
4. **R3 承诺未兑现**。03 文档承诺"M4 冻结语义化版本"，实际版本号仍 0.1.0 且 API 仍在破坏性迭代（fit_transform 即 M6 后新增）。版本策略需要一次明确的了断。
5. **文档滞后于能力**。README/skill 之外，docs.rs 上 crate 无文档建设；示例即文档的优势未制度化。

## 1. 功能补齐：缺失点梳理与优先级

对照 manim 能力清单与本项目定位（agent 友好、单二进制、教学视频），缺失功能分五档：

### P0 —— 阻断核心定位（下一版本必做）

| 功能 | 现状缺口 | 验收标准 | 理由 |
|---|---|---|---|
| **1080p 性能基准** | NF1/R4 从未实测 | `benches/render.rs`（criterion）：1080p 单帧 CPU 渲染 + rgb24 管道吞吐数字入库 docs；若 <30fps 找出瓶颈并出方案 | 项目核心卖点"快"至今只有 540p 数据 |
| **相机系统** | 完全缺失 | `Camera` 结构（center/zoom/rotation），作为普通 Item 挂 Timeline 可动画；fourier 示例加一段推近镜头验证 | 手摆坐标是创作验证中最大的痛点（strip 迭代两轮修构图） |
| **富文本 Text** | 只能 outline_text 单字体单样式 | `Text` 高层 API：字号/行距/粗细混排，走 Typst 引擎（复用 Formula 管线）；中文/英文混排不出框 | 标题/字幕是教学视频刚需，当前中文字体硬编码路径绕过 |

### P1 —— 显著提升创作效率（v0.3）

| 功能 | 说明 | 验收标准 |
|---|---|---|
| 动画组 `Anim::group` + `lagged_start` | manim 手感核心；当前逐项 play + overlap 手工对齐（M3 踩过的坑） | group 内子动画自动错开 step；公式 Write 用 group 重写后代码行数减半 |
| SVG 导入 | 图标/插图入场 | `Item::from_svg(path)`，走 usvg 转 kurbo 路径 |
| 图片支持 | `Item::from_image`（含 PNG/JPEG 解码，image 依赖已有） | 示例中图片淡入 + transform |
| GIF/WebM 输出 | 编码后端扩展 | `render --format gif`（短视频传播场景） |
| 预览循环 + 时间 seek | preview 只支持帧号，不支持按秒跳转和循环播放 | `--loop`；拖动条支持秒显示 |

### P2 —— 生态与打磨（v0.4+）

- **场景参数 JSON**：`render --config scene.json` 把尺寸/fps/时长外置（兑现"数据驱动"对场景参数的承诺，当前只有主题外置）。
- **模板画廊**：scaffold 增加 chart/proof 两个模板。
- **音频事件对齐**：BGM 静音段检测（ffanim-audio analyze 已有）反向驱动 timeline 插入 wait（自动卡点雏形）。
- **字幕轨**：`SubtitleTrack` 与 mux 合并字幕流。

### 明确不做（保持尖锐）

3D、插件系统、Python 绑定、实时协作——与"单二进制数学动画"定位冲突，写入文档防止范围蔓延。

## 2. 架构评估与优化

### 2.1 分层合理性：✅ 保持

```
ffanim-core（无渲染依赖，依赖根）
  ├─ ffanim-typst   ┐
  ├─ ffanim-render  ├─ 平行能力层，互不依赖
  ├─ ffanim-encode  ┘
  ├─ ffanim-audio   （仅依赖 core）
  └─ ffanim-preview （core + render）
ffanim（门面，re-export 全能力）
  └─ ffanim-cli / examples（面向用户）
```

这个分层经受住了 M1~M6 全部实战验证（GPU/CPU 切换、ffmpeg 替换 libav、preview 复用 CpuBackend），**不动**。

### 2.2 需要修正的三个点

**A. encode 解除对 core 的重依赖**

encode 只用 `Error/Result`。方案：core 的 Error 是 thiserror enum，encode 自建轻量错误并在门面统一转换；或（更简单）core 拆出 `ffanim-error` 微 crate，error.rs/style 下沉。**决策：采用后者但推迟**——先做 §5 拆分，若 core 拆分后 Error 单独成文件，顺手下沉为独立 crate（成本一次性，收益是 encode 可被纯工具链复用）。

**B. 门面 re-export 需要制度化**

`ffanim::typst` / `ffanim::audio` / `ffanim::tools` 三个模块是 M6 应急产物，无文档无组织原则。规范（§3 落地）：
- 门面按"用户工作流"分组而非按内部 crate 分组：`scene`（Item/Axes/Font/Theme）、`anim`（Timeline/Anim/RateFunc/Updater）、`media`（audio/tools/encode）、`math`（typst）。
- 规则：**examples/ 中出现的每个符号必须能从门面根 `ffanim::` 到达**；门面不允许出现内部 crate 名暗示（如 `ffanim::ffanim_typst_xxx`）。

**C. cli 直接依赖全部 crate → 收敛到门面**

cli 目前 7 个依赖。除 preview/scaffold（编译体积考虑）外，场景代码一律走门面。收益：cli 即"门面 API 的活文档"，门面缺什么一目了然。

### 2.3 交互关系不变式（写死，防架构漂移）

1. core 不出现任何渲染/编码/音频符号（kurbo 几何类型除外）。
2. 平行能力层（typst/render/encode/audio）互相零依赖。
3. 所有纯函数求值（render_frame）不允许 I/O；I/O 只存在于 encode/audio/cli。
4. 每个后端必须能被 `RenderBackend` trait 表达（新增后端如 Skia 走此口）。

## 3. API 设计规范

### 3.1 命名规范（对现有 API 做一次对齐审查）

| 类别 | 规范 | 现有正面例子 | 待修正 |
|---|---|---|---|
| 构造器 | `Item::circle/rect/regular_polygon/from_path` | ✅ | — |
| Builder 链 | 消耗 self 返回 Self：`with_fill/with_stroke/during/rate` | ✅ | — |
| 变换 | 几何动词开头：`fit_transform/center_transform` | ✅ | — |
| 配置注入 | `with_min_duration/from_system`（with_* 语义=派生修改） | ✅ | — |
| 求值 | 纯函数名 = 动词：`render_frame/eval/outline_text` | ✅ | — |
| 时长单位 | 一律秒（f64）；帧数只出现在 Compiled 层（`_frames` 后缀） | ✅ | 检查 preview 内部混用处 |
| 缩写禁令 | 禁止 `tl`/`cx` 出现在 pub API 参数名（`timeline`/`center_x`） | ⚠️ fit_transform 参数 `cx, cy` 需斟酌——保留（几何惯用缩写，manim 同款） | — |

### 3.2 错误处理机制

1. 库层错误统一 `ffanim_core::Error`（thiserror），禁止 anyhow 进入库。
2. 每个错误变体必须携带定位信息（已有 `FontIo(path)` 模式）——审查所有变体：**禁止裸 `Error::Msg`**。
3. 用户可见错误消息格式：`<发生了什么>（在哪/怎么办）`，CI 加 clippy::result_unit_err 意识。
4. 公开 API 禁止 panic：`unwrap/expect` 只允许出现在测试与 `// SAFETY:` 不适用的不变式断言处（每个 expect 必须写注释说明为何不可能失败）。

### 3.3 版本策略（了断 R3 遗留）

- 现在到 v0.2.0：允许破坏性变更（§5 拆分本身会动模块路径）。
- **v0.2.0 起执行 semver 0.x 规则**：破坏性变更 → minor +1；新功能 → minor；修复 → patch。
- 每次 minor 发布必须：CHANGELOG 条目 + 里程碑 tag `vX.Y` + 示例全通。
- MSRV：跟随工具链最新 stable（项目声明 1.95），CHANGELOG 记录 MSRV 变更。
- 破坏性变更必须在门面保留 deprecation 提示一个版本（`#[deprecated]` 包装），除非该 API 从未出现在任何发布 tag。

### 3.4 API 质量门禁（可衡量）

CI 新增 lint：

```toml
[workspace.lints.rust]
missing_docs = "warn"          # 公开项必须有文档注释
```

- 规则 A：`cargo doc --no-deps` 零警告（CI 门禁）。
- 规则 B：每个 pub API 至少被一个 example 或 test 引用（脚本 `scripts/api_coverage.sh` 对比 `cargo doc` 符号表与 examples 用量，v0.3 起门禁）。
- 规则 C：门面根符号（`ffanim::` 可达）数量在 CHANGELOG 中记录，防止无意识膨胀（当前基线约 40 个）。

## 4. 源码拆分方案（精细化模块化）

原则：**按职责拆，不按行数拆**；拆分 = 移动代码 + 调整 pub use，公开 API 零变化（门面用户无感知）。

### 4.1 ffanim-core（timeline.rs 869 行 → 4 文件）

| 新文件 | 承载 | 行数估计 |
|---|---|---|
| `anim.rs` | Anim、AnimKind、动画构造器（create/fade_in/transform/set_value…） | ~200 |
| `tracker.rs` | Updater、TrackerId、求值信号节点 | ~80 |
| `timeline.rs` | Timeline 构建器（play/wait/overlap/compile）+ ScheduledAnim | ~250 |
| `eval.rs` | CompiledTimeline、render_frame、tracker_value/morph_items/lerp_paint 等求值辅助 | ~340 |

`lib.rs` 的 re-export 路径不变 → 对外零破坏。验收：`cargo test --workspace` 全绿 + snapshot 基准三帧 PASS。

### 4.2 ffanim-cli（main.rs 651 行 → 命令模块）

```
src/
  main.rs          # 仅 clap 定义 + match 分发（~120 行）
  cmd/
    render.rs      # render / timeline / frame（同族）
    inspect.rs     # inspect / snapshot（基准对）
    tools.rs       # strip / onion（转发 ffanim_render::tools）
    scaffold.rs    # new / info
    audio.rs       # audio
    preview.rs     # preview（winit 事件循环入口）
  scenes.rs        # 保持
  demo.rs          # 保持
```

每个 handler 是 `pub fn run(args: &XxxArgs) -> Result<()>`，参数直接复用 clap derive 结构。验收：`ffanim --help` 输出与现在逐字一致（防止 CLI 语义意外变化）。

### 4.3 ffanim-typst（lib.rs 600 行 → 3 文件）

| 新文件 | 承载 |
|---|---|
| `engine.rs` | TypstEngine、内部 TypstWorld、LRU 缓存（typst 库唯一接触面） |
| `formula.rs` | Formula、FormulaPiece、FormulaOptions、fit/center_transform、to_items |
| `match.rs` | match_formulas、MatchPlan、LCS 配对算法 |

### 4.4 其余 crate（阈值判断）

- ffanim-render：已达标（lib/cpu/gpu/tools 各司其职），不动。
- ffanim-audio（277 行）：analyze 与 mux 职责清晰，**暂不拆**；超过 400 行再拆。
- ffanim-encode（294 行）：pipeline 与 mux 两段职责，暂可容忍；若 §2.2A 下沉错误类型时一并拆 `pipeline.rs + mux.rs`。
- ffanim-preview：事件处理（input）与绘制循环（draw）可拆两文件，低优先级，随 P1 预览增强时顺手做。

**执行方式**：纯移动提交，一个 crate 一个 commit（`refactor(core): timeline 按职责拆分四模块`），拆分前先跑全量测试留档，拆分后逐项对比。

## 5. 工程化体系

### 5.1 构建与发布

| 项 | 方案 | 验收 |

| 任务编排 | 仓库根 `justfile`（just 单二进制，agent 友好）：`just ci` / `just demo` / `just fourier` / `just bench` | 新人一条命令复现全部验收产物 |

### 5.2 质量保障

1. **测试金字塔补全**（当前只有内联单测）：
   - core：`tests/timeline_integration.rs`——示例驱动：demo/formula_demo/sine_demo 三场景的 timeline 构建与关键帧断言（不渲染，纯 eval，快）。
   - render：`tests/golden.rs`——PNG 快照与 `frames/baseline/` 逐像素对比（现有 snapshot CLI 逻辑下沉为测试宏）。
   - encode/audio：契约测试用假 PCM/假 ffmpeg（`FFANIM_FFMPEG_BIN` 环境变量注入假实现，测管道协议与错误路径）。

2. **性能回归门禁**：criterion bench（1080p 单帧、timeline compile 1万动画）入库；CI 不跑 bench（太慢），但 benchmark 数字随版本记录在 `docs/benchmarks.md`，异常 >20% 回退必须说明。
3. **代码规范**：现有 workspace lints 基础上加 `missing_docs` + `clippy::pedantic` 中逐条豁免采纳（不许整组开启）；`unsafe_code = forbid` 保持。
4. **Agent 验证循环制度化**：把"timeline → inspect → render → strip → snapshot"写进 CONTRIBUTING.md，作为任何视觉相关 PR 的强制验收路径。

## 7. 度量与调整机制

**可执行**：每个工作项有唯一验收命令（测试/基准/逐字对比/门禁 lint），不依赖主观判断。
**可衡量**：
- 每版本记录四张表进 CHANGELOG：门面 API 数、测试数（单测/集成）、编译依赖数、bench 关键数字（1080p fps、实时率）。
- 里程碑完成定义（DoD）：验收示例通过 + 文档/CHANGELOG 更新 + tag 打标 + 下一步候选写入 docs/04。

**可调整**（触发重规划的条件）：
1. M7 bench 显示 NF1 已达标 → M8.5 降级为记录性工作，提前 crates.io。
2. Typst/vello 上游 breaking 且无迁移路径 → 冻结版本区间并在 CHANGELOG 声明，路线顺延一个版本。
3. 任何"明确不做"清单项被新需求冲击 → 先在 docs/04 追加决策记录再动工。
4. 连续两个里程碑延期 → 砍 P1 清单尾部（功能永不欠债，欠债只允许在技术债台账有编号地欠）。
