# 性能基准（benchmarks）

依据 docs/04-项目优化规划.md §5.2 规则 B：基准数字随版本记录于此，**异常 >20% 回退必须在 CHANGELOG 说明**。
运行方式：`just bench`（criterion，release profile）。CI 不跑 bench（太慢），发版前手动执行。

## 环境基线

| 项 | 值 |
|---|---|
| 日期 | 2026-10-12 |
| CPU | AMD Ryzen 7 7840HS（8C/16T Zen4，最高 5.14GHz） |
| GPU | AMD Radeon 780M（iGPU；本基准走 CPU 路径，GPU 后端另行记录） |
| 工具 | criterion 0.7，100 采样，release |
| 场景 | 1080p（1920×1080@30），60 对象（圆/矩形混合）淡入动画，第 45 帧中段采样 |

## v0.2.0 基线（M7.6，criterion）

| 基准 | 中位数 | 区间 | 吞吐 |
|---|---|---|---|
| `cpu_render_1080p`（求值 + CPU 光栅化，单帧） | **26.43 ms** | 26.06–26.81 ms | 37.8 fps |
| `rgb24_pack_1080p`（RGBA8→RGB24 打包，≈6.2 MB/帧） | **1.195 ms** | 1.193–1.197 ms | ≈5.2 GB/s |

## NF1 / R4 结论（docs/03 §NF1、docs/04 §1 P0）

- **NF1 达标**：渲染 26.43ms + 打包 1.20ms ≈ 27.6ms < 33.3ms（1080p30 帧预算），
  CPU 单帧路径实时率 **≈1.21x**（37.8 fps > 30 fps），未触发"找出瓶颈"条款；
- **R4 定论**：RGB24 打包 5.2 GB/s ≫ 需求（6.2 MB × 30 fps ≈ 187 MB/s），
  **管道带宽不是瓶颈**——1080p 实时性约束在 CPU 光栅化本身；
- 对 M8.5 的指导：若未来场景（更高对象数/GPU 不可用）跌破实时，
  优化方向优先级 = 光栅化热点 > 求值热点 > 管道带宽（最后者已证非瓶颈）。

## 复现

```sh
just bench          # criterion 全量（≈2 分钟）
```

基线数字同时写入当版 CHANGELOG（§5.2 规则 C：门面 API 数 / 测试数 / 依赖数 / bench 关键数字四表齐全）。
